## Phase 1.15 チュートリアル方針

Phase 1.15では、初心者が迷わず操作できるように、説明を一度に出す方式から一時停止型チュートリアルへ移行します。

- 初心者向けチュートリアルでは、1回に1概念だけ説明する
- 滑走路1本1機ルール、着陸許可、滑走路離脱、ゲート誘導を段階的に教える
- 説明中はゲーム進行を止め、「次へ」ボタンで進める
- 操作段階では、対象の航空機や指示ボタンに注目させてから操作させる
- チュートリアル中は遅延評価を厳密に行わず、正しく操作している初心者に不自然な減点を与えない
- Pushback、Hold Short、Contact Ground、Contact Tower、Contact Departure、フライトストリップ、レーダー/ミニマップ、空港俯瞰ビュー、経路プレビュー、スコアランク制、英語音声は後続Phaseで扱う

## Phase 1.15 QA修正メモ

Unity Play確認後のQA修正として、以下をPhase 1.15内で対応しました。

- チュートリアル文字の視認性を改善するため、文字サイズ、パネル余白、背景コントラストを調整する
- チュートリアル中は、説明と操作案内を1か所のチュートリアルパネルに統一する
- 通常の下部操作ガイドは、チュートリアル中には重複表示しない
- 最終結果画面は `訓練完了`、`安全度`、`遅延`、`処理機数` の日本語表示にする
- チュートリアル中の遅延評価は緩和し、正しい操作をしている初心者に不自然な減点を与えない
- 下部パネルは将来的に、日本語中心の管制通信ログへ発展させる
- 英語音声は将来Phaseで扱い、Phase 1.15では実装しない
- 遅延・効率評価の本格設計はPhase 3.2で扱う

## 下部パネルと通信ログの方針

Phase 1.15〜1.2では、下部パネルはチュートリアル説明と次の操作案内に使います。
Phase 1.7では、この下部パネルを管制官とパイロットの通信ログ表示へ発展させます。

- 通信ログは初心者向けに日本語表示を基本にする
- 将来的に英語音声を追加する
- 音声は英語、画面表示は日本語または日英併記にする
- 表示例: 管制官：AJJ101、A滑走路への着陸を許可します。
- 音声例: AJJ101, cleared to land Runway A.

## 評価設計の方針

現在の `Delay` は暫定的な指標です。
チュートリアル中は遅延評価を厳密に行わず、適切な操作をしているプレイヤーに不自然な減点を与えない方針にします。

Phase 3.2では、既存航空管制ゲームも参考にしながら、効率性評価を設計します。

将来の評価候補:

- 安全度
- 遅延
- 処理機数
- 滑走路稼働率
- 指示待ち時間
- ルート効率
- 総合ランク S/A/B/C

## 将来のUI方針

現在の右側固定の指示欄は、Phase 1用の暫定UIです。
将来的には、既存の航空管制ゲームに近い形で、左側に到着 `ARRIVAL` と出発 `DEPARTURE` のフライトストリップを配置し、そこを操作の中心にします。

- 航空機を直接クリックする方式から、フライトストリップの便名帯をクリックして選択する方式へ移行する
- 到着機と出発機は別欄で管理する
- Phase 2.2では、到着欄にAJJ101 / AJJ103、出発欄にAJJ202 / AJJ204を表示する
- 複数機はまずストリップで一覧・選択できることを優先し、詳細は右下詳細パネルに分離する
- 追加機の完全な状態遷移、時間差スポーン、衝突判定、安全管理は後続Phaseで扱う
- 各ストリップには、便名、機種、使用滑走路、Spot、現在状態、担当管制ポジションを表示する
- Phase 2.3では、左側に到着 `ARRIVAL` と出発 `DEPARTURE` のストリップ欄を追加し、ストリップクリックでも航空機を選択できるようにする
- 選択中ストリップと推奨指示待ちのストリップは、色や短いテキストで分かるようにする
- ストリップは一覧性を優先し、便名、機種、RWY、SPOT、短い状態/推奨指示だけを表示する
- Phase 2.3 QA再修正以降、ストリップは横長の細い長方形にし、原則として便名 + RWY/SPOTのみを表示する
- 便名は大きく、RWY/SPOTは小さく表示する
- 機種、状態、推奨指示、出発地、到着地、時刻は右下詳細パネルへ移す
- 時刻、出発地、到着地、詳細ルートは、将来的な右下詳細パネルへ分離する
- 右側固定の指示欄は暫定UIであり、Phase 2.4以降は選択したストリップの中または近くに、その機体へ出せる指示ボタンを表示する
- Phase 2.4では、選択中ストリップの右側に現在出せる指示を独立したコマンドポップアップで表示し、右側固定指示欄と同じ既存コマンド処理を呼び出す
- コマンドポップアップはストリップ領域から右にはみ出してもよく、ボタン内の日本語/英語2行が潰れない幅と高さを確保する
- 将来的に最大4個程度のボタンを縦に並べられる構造を想定する
- ストリップ下に指示ボタンを置かず、到着/出発リストの縦方向の一覧性を維持する
- 1機に対して常に全ボタンを表示せず、現在状態で出せる指示だけを1〜2個表示する
- Phase 2.4.5では、右側固定指示ボタンを通常操作では表示せず、選択中ストリップ右側のコマンドポップアップを主操作にする
- チュートリアルと通常ガイドは、航空機Objectクリックではなくストリップ選択を主導線として案内する
- 航空機Objectクリックは当面、補助操作として維持する
- 右側エリアは将来的に、右上の簡易レーダー/ミニマップと右下の選択中航空機詳細を置く場所として整理する
- Phase 2.5では、右上に見るだけの簡易ミニマップを追加し、RWY 18L、誘導路、SPOT 01〜04、航空機位置を表示する
- ミニマップ上では選択中航空機を強調する
- Phase 2.5 QAでは、ミニマップ全体と内部要素を拡大し、複数機の位置関係を読み取りやすくする
- ミニマップ上のクリック操作、航空機選択、経路指定、経路プレビューは後続Phaseで扱う
- Phase 2.xでは操作構造を優先し、フォント、色、枠、ボタン質感、航空管制ゲームらしいHUD表現はPhase 6.1 UI Visual Polishで扱う
- 下部には将来的に、管制官の指示文とパイロットの復唱ログを表示する

## Phase 2.0 航空機データ方針

Phase 2.0では、今後のフライトストリップ、レーダー、複数機運用、那覇空港モデル化に備えて、航空機と滑走路のデータを整理しました。

- 航空機は、便名、機種、運航種別、使用滑走路、Spot、状態、担当管制ポジション、出発地/目的地、nextTarget、推奨コマンドIDを持つ
- 航空機は将来的に、scheduledDepartureTime、estimatedDepartureTime、actualDepartureTime、scheduledArrivalTime、estimatedArrivalTime、actualArrivalTime、delayMinutesを持つ
- 機種は `B737級` のような曖昧表記ではなく、`B737` / `A320` のような機種名表記を基本にする
- AJJ101は到着機、B737、宮崎発・那覇着、SPOT 01、A滑走路（RWY 18L）として扱う
- AJJ202は出発機、A320、那覇発・東京着、SPOT 02、A滑走路（RWY 18L）として扱う
- A滑走路は内部データ上、`RWY_A`、18L/36R、現在使用18Lとして扱う
- B滑走路は内部データ上、`RWY_B`、18R/36L、将来拡張用、未解放として残す
- 初心者向けUIでは「A滑走路」を基本表記にし、必要な場所だけ「A滑走路（RWY 18L）」または `RWY 18L` のように併記する
- 外部表示では `RWY 18L` / `SPOT 01` のような短い目的地表示を使う
- 機体ラベルは、便名、機種、次目的地だけを短く表示する
- 将来的に、情報表示は左側フライトストリップ、右下詳細、機体ラベルへ役割分担する
- 右下詳細UIでは、便名、機種、到着/出発、出発地、到着地、予定時刻、推定時刻、実績時刻、遅延分、現在RWY、現在SPOT、現在状態、担当管制ポジション、次の推奨指示、簡易ルートを表示する想定にする
- Phase 2.3 QA再修正では、右下詳細パネルに選択中航空機の便名、機種、到着/出発、出発地/到着地、予定時刻、RWY、SPOT、状態、担当管制、次の推奨指示を表示する
- 右下詳細UIの本格実装は後続Phaseで検討する
- 遅延や効率性評価の本格実装はPhase 3.2で扱う
- 出発承認 / Departure ClearanceはPhase 3.4候補とし、Pushback、Taxi、Line Up、Takeoffとは別概念として整理する
- 管制文テンプレートは将来的に、`A滑走路`から`RWY 18L` / `Runway 18L`へ切り替えられるようにする
- プッシュバック車両/TowCarの見た目や実アニメーションは、Phase 6.0以降またはPhase 10.0相当の没入感強化で扱う
- Phase 2.0完了後の次Phaseは、複数機運用より先にPhase 2.3「フライトストリップ方式」を準備する
