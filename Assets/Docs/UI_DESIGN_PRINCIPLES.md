# UI Design Principles

ATCJourneyJapanのUI設計原則です。
実装前にこのファイルを確認し、現在Phaseの範囲に合うUIだけを追加します。

## 基本方針

- 初心者向けの初期表示は日本語優先
- 管制ボタンは日英併記を基本にする
- ボタンは2行表示を前提にする
- 推奨ボタンは緑でハイライトする
- 状態に合わないボタンは非表示または無効化する
- PCブラウザ/WebGLとスマホ横画面の両方を意識し、タップしやすいボタンサイズにする

## チュートリアル方針

- チュートリアルでは1回に1概念だけ説明する
- チュートリアル説明中はゲーム進行を一時停止する
- チュートリアル中は説明と操作案内を1か所に統一する
- 1画面に同じ意味の文章を2か所出さない
- 教官的な説明や次に行う操作の説明は、中央下のチュートリアルパネルに統一する
- 画面中央は空港状況を見る場所なので、常時大きなUIを置かない
- 中央の空港ビューは航空機・滑走路・誘導路を見る場所であり、常時大きなチュートリアルパネルで隠さない
- チュートリアル説明パネルはコンパクトにし、空港状況の視認性を優先する
- 文字は大きめにし、背景とのコントラストと余白を確保する

## Phase 1 UI

- 右側固定の指示欄はPhase 1用の暫定UIである
- 下部パネルはPhase 1.7以降、管制官の指示ログ表示に使う
- 初回チュートリアル中は読みやすさを優先し、簡易ログとして管制官の指示のみ表示する
- パイロット復唱はログが長くなりすぎるため、Phase 1.8以降で詳細ログ候補として検討する
- 通信ログは初心者向けに日本語表示を基本にする
- 下部ログは直近の管制指示を表示する場所とし、高さを取りすぎない
- チュートリアル説明と管制ログは役割を分け、同じ意味の文章を複数箇所に出さない
- 将来的には「簡易ログ: 管制官の指示のみ」と「詳細ログ: 管制官の指示 + パイロット復唱」の切り替えを検討する
- Phase 1.8以降、管制文は commandId / 日本語管制文 / 英語管制文 / パイロット復唱候補 / futureAudioKey を持つテンプレートとして整理する
- 初期表示は日本語の管制官指示のみとし、将来的に日本語 / 英語 / 日英併記の表示切替を検討する
- futureAudioKey は将来の英語音声ファイル管理に使う想定であり、音声再生自体は後続Phaseで扱う

## 将来UI

- 将来的には左側フライトストリップ中心UIへ移行する
- 到着機と出発機は別欄で管理する
- 各ストリップには便名、機種、滑走路、Spot、状態、担当管制ポジションを表示する
- Phase 2.3では、左側に到着 ARRIVAL / 出発 DEPARTURE のストリップ欄を置き、ストリップクリックでも航空機を選択できるようにする
- 選択中ストリップと推奨指示待ちストリップは、色や短いテキストで分かるようにする
- Phase 2.3 QA以降、ストリップは一覧性を最優先し、便名、機種、RWY、SPOT、短い状態/推奨指示に絞る
- Phase 2.3 QA再修正以降、ストリップは横長で細い長方形とし、原則として便名 + RWY/SPOTのみを表示する
- ストリップでは便名を最も目立たせ、RWY/SPOTをすぐ読める位置に置く
- ストリップでは便名を大きく、RWY/SPOTを小さく表示する
- ストリップには機種、状態、推奨指示、時刻、出発地、到着地、詳細ルート、長い説明文を詰め込まない
- Phase 2.2では、到着欄にAJJ101 / AJJ103、出発欄にAJJ202 / AJJ204を表示し、まず複数機を一覧・選択できることを優先する
- 複数機表示でもストリップ本体は便名 + RWY/SPOTのみを維持し、詳細は右下詳細パネルへ分離する
- 追加機はチュートリアル完了条件には含めず、既存のAJJ101/AJJ202初回訓練フローを優先する
- 航空機Objectクリックは当面維持するが、将来的には補助操作にする
- 右側固定の指示欄は暫定UIであり、将来的には選択中ストリップ内またはストリップ横に指示ボタンを統合する
- 操作対象と指示ボタンを近づけ、どの便へ指示を出しているか分かりやすくする
- Phase 2.4では、選択中ストリップの右側にその航空機へ現在出せる指示を独立したコマンドポップアップとして表示する
- コマンドポップアップはストリップ領域から右にはみ出してもよく、ストリップ本体へボタンを押し込まない
- コマンドポップアップ内のボタンは、日本語/英語2行が潰れない幅、高さ、余白、文字サイズを確保する
- 将来的に最大4個程度のコマンドボタンを縦に並べられるレイアウトを想定する
- ストリップ連動コマンドボタンはストリップ下に置かず、到着/出発リストの縦方向の一覧性を維持する
- ストリップ本体は便名 + RWY/SPOTの一覧表示に絞り、指示ボタンは選択中ストリップにだけ付ける
- 1機に対して常に全ボタンを表示せず、現在状態で出せる指示だけを1〜2個表示する
- プレイヤーにボタン探しをさせず、どの機体にいつ指示を出すかへ集中させる
- ストリップ右側ボタンは、選択中航空機の現在状態に応じたコンテキストコマンドとして扱う
- ストリップ側ボタンと右側固定指示欄は同じ既存コマンド処理を呼び出し、管制ログと状態遷移を共通化する
- Phase 2.4.5以降、右側固定指示ボタンは通常操作では表示せず、ストリップ右側のコマンドポップアップを主操作にする
- チュートリアルや通常ガイドでは、航空機Objectクリックではなくストリップ選択を基本導線として案内する
- 航空機Objectクリックは当面補助操作として維持し、ストリップ操作に慣れないプレイヤーの逃げ道にする
- 右側エリアは大きな固定指示ボタンの置き場に戻さず、右上は簡易レーダー/ミニマップ、右下は選択中航空機詳細の表示場所として使う
- Phase 2.5 QA前UI整理以降、右上教官コメント欄は使わず、右上はミニマップ/レーダー専用の状況把握エリアにする
- 同じ説明を右上教官コメントと中央下チュートリアルに重複表示しない
- ストリップは一覧と選択、ストリップ近くの指示ボタンは選択中航空機への操作、右下詳細は選択中航空機の詳細、下部は管制ログとして役割を分ける
- Phase 2.5の右上ミニマップは、複数機の位置関係を見るための状況把握UIにする
- ミニマップにはRWY 18L、誘導路、SPOT、航空機位置を簡易表示し、選択中航空機を強調する
- Phase 2.5 QA以降、ミニマップは小さすぎる装飾ではなく、複数機の位置関係を一目で確認できるサイズにする
- 滑走路、誘導路、SPOT、航空機点、選択中航空機ラベルは、画面右上でも読める大きさを優先する
- Phase 2.5では、ミニマップ上のクリック操作、航空機選択、経路指定、経路プレビューは行わない
- ミニマップは右下詳細、中央空港ビュー、中央下チュートリアルを隠さないサイズと位置にする
- Phase 2.0以降、初心者向けの基本表記は「A滑走路」を維持しつつ、必要な場所では「A滑走路（RWY 18L）」のように実滑走路番号を併記できるようにする
- フライトストリップでは、便名、機種、出発地/目的地、滑走路、Spot、状態、担当管制ポジション、推奨コマンドを小さく整理して表示する
- 実滑走路番号は将来の管制文、英語音声、レーダー/ミニマップで使う情報として扱い、初心者向けUIに一度に出しすぎない
- 機体ラベルは、便名、機種、次目的地だけを短く表示する。状態や詳細情報を詰め込まない
- 次目的地は`RWY 18L` / `SPOT 01` / `HOLD A`のような短い表記を基本にする
- 選択中航空機の詳細は将来的に右下へ分離し、左下パネルへ全情報を集約しない
- 右下詳細UIの本格実装は後続Phaseで検討する
- 詳細情報は一覧性を落とさないよう、ストリップではなく将来の右下詳細パネルへ分離する
- 右下詳細パネルには、便名、機種、到着/出発、出発地、到着地、予定時刻、推定時刻、実績時刻、遅延分、現在RWY、現在SPOT、現在状態、担当管制ポジション、次の推奨指示、簡易ルートを表示する想定にする
- Phase 2.3 QA再修正では、右下詳細パネルに便名、機種、到着/出発、出発地/到着地、予定時刻、RWY、SPOT、状態、担当、次の推奨指示を表示する
- 右側固定の指示欄はPhase 2.4.5で通常操作から外し、ストリップ側へ統合する
- 右上には将来的に簡易レーダー/ミニマップを表示する
- 将来的に英語音声を追加する
- 音声は英語、画面表示は日本語または日英併記にする

## 3D / Visual Upgrade方針

- 現在の空港表示は、Unity 3D空間上の簡易俯瞰プロトタイプとして扱う
- 見た目が2Dマップ風でも、Phase 2.x〜3.xではゲーム構造、ストリップ、ミニマップ、安全管理を優先する
- 本格的な3D空港ビュー化はPhase 6.0以降で扱う
- Phase 6.0では、航空機モデル、滑走路/誘導路/SPOTの3Dパーツ化、管制塔風の斜め俯瞰カメラを検討する
- Phase 7.0では、那覇空港らしさ、海、ターミナル、管制塔、RWY 18L/36R と RWY 18R/36L の2本滑走路構造を検討する

## 将来コマンド設計方針

- 出発便コマンド候補: Flight Clearance、Pushback、Pushback Direction、Taxi Permit、滑走路/誘導路ルート選択、Line Up and Wait、Cleared for Takeoff、Hand-off to Departure
- 到着便コマンド候補: Approach Contact、Runway Select / ILS Approach、Clear to Land、Go-Around、Hand-off to Ground、Taxi to Spot
- 共通/緊急コマンド候補: Hold Taxi、Resume Taxi、Go-Around、Hand-off
- Flight Clearance / 出発承認はPhase 3.4で扱う
- Hold Taxi / Resume TaxiはPhase 3.0で扱う
- Go-AroundはPhase 3.0〜3.2の緊急・救済コマンドとして扱う
- Hand-offはPhase 3.5で扱う
- Pushback方向選択やTaxiルート選択は、Phase 3.0以降またはステージ制導入後に扱う

## Visual Polish方針

- Phase 2.xでは、見た目の磨き込みよりも操作構造を優先する
- フォント統一、ストリップの質感、ボタンデザイン、選択中/指示待ち/警告の視覚表現はPhase 6.1 UI Visual Polishで扱う
- 航空管制ゲームらしいHUD表現やアイコン追加もPhase 6.1以降で検討する
