# UI Design Principles

ATCJourneyJapanのUI設計原則です。
実装前にこのファイルを確認し、現在Phaseの範囲に合うUIだけを追加します。

## 基本方針

- 初心者向けの初期表示は日本語優先
- 管制ボタンは日英併記を基本にする
- ボタンは2行表示を前提にする
- 推奨ボタンは緑でハイライトする
- 状態に合わないボタンは非表示または無効化する
- PCブラウザ/WebGLとスマホ横画面の両方を意識し、タップしやすいボタンサイズにする

## チュートリアル方針

- チュートリアルでは1回に1概念だけ説明する
- チュートリアル説明中はゲーム進行を一時停止する
- チュートリアル中は説明と操作案内を1か所に統一する
- 1画面に同じ意味の文章を2か所出さない
- 画面中央は空港状況を見る場所なので、常時大きなUIを置かない
- 中央の空港ビューは航空機・滑走路・誘導路を見る場所であり、常時大きなチュートリアルパネルで隠さない
- チュートリアル説明パネルはコンパクトにし、空港状況の視認性を優先する
- 文字は大きめにし、背景とのコントラストと余白を確保する

## Phase 1 UI

- 右側固定の指示欄はPhase 1用の暫定UIである
- 下部パネルはPhase 1.7以降、管制官の指示ログ表示に使う
- 初回チュートリアル中は読みやすさを優先し、簡易ログとして管制官の指示のみ表示する
- パイロット復唱はログが長くなりすぎるため、Phase 1.8以降で詳細ログ候補として検討する
- 通信ログは初心者向けに日本語表示を基本にする
- 下部ログは直近の管制指示を表示する場所とし、高さを取りすぎない
- チュートリアル説明と管制ログは役割を分け、同じ意味の文章を複数箇所に出さない
- 将来的には「簡易ログ: 管制官の指示のみ」と「詳細ログ: 管制官の指示 + パイロット復唱」の切り替えを検討する
- Phase 1.8以降、管制文は commandId / 日本語管制文 / 英語管制文 / パイロット復唱候補 / futureAudioKey を持つテンプレートとして整理する
- 初期表示は日本語の管制官指示のみとし、将来的に日本語 / 英語 / 日英併記の表示切替を検討する
- futureAudioKey は将来の英語音声ファイル管理に使う想定であり、音声再生自体は後続Phaseで扱う

## 将来UI

- 将来的には左側フライトストリップ中心UIへ移行する
- 到着機と出発機は別欄で管理する
- 各ストリップには便名、機種、滑走路、ゲート/スポット、状態、担当管制ポジションを表示する
- Phase 2.0以降、初心者向けの基本表記は「A滑走路」を維持しつつ、必要な場所では「A滑走路（RWY 18L）」のように実滑走路番号を併記できるようにする
- フライトストリップでは、便名、機種、出発地/目的地、滑走路、ゲート/スポット、状態、担当管制ポジション、推奨コマンドを小さく整理して表示する
- 実滑走路番号は将来の管制文、英語音声、レーダー/ミニマップで使う情報として扱い、初心者向けUIに一度に出しすぎない
- 右上には将来的に簡易レーダー/ミニマップを表示する
- 将来的に英語音声を追加する
- 音声は英語、画面表示は日本語または日英併記にする
